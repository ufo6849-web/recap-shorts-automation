# 소재 목록 가짜뉴스 체크 계획 (2026-11-05)

## 1. 목표

소재(인기글) 목록에서 만들 글을 고르기 전에 가짜뉴스를 걸러 낸다.

- 목록 위에 "가짜뉴스 체크" 단추를 둔다.
- 누르면 보이는 글 가운데 시사 글만 제목으로 판정한다. 돌리기 전에 "시사 12건 · 약 $0.70"처럼 건수와 예상 비용을 보여 준다.
- 판정이 끝난 글에는 의심·주의·통과 칩을 붙인다. "가짜 의심 숨기기" 토글로 의심 글을 뺄 수 있다.
- 결과는 글마다 보관해 다시 묻지 않는다.
- 사용자 승인: 2026-11-04 "1번권장으로 가자"(목록 위 단추 하나와 숨기기 토글, 수동 실행).

제목 판정은 거르기용 참고 값이다. 고른 글은 제작 단계에서 본문·그림까지 보는 기존 사실 확인(feat/factcheck)을 그대로 거친다. 제목 판정의 "통과"가 그 확인을 대신하지 않는다.

## 4. 설계

### 4.1 흐름

1. **분류(단추를 누르면, 비용 거의 0):** 보이는 글의 제목을 Flash에 묶음 30으로 보내 시사/일반을 나눈다.
   - 분류 결과는 글마다 보관한다.
   - 제목은 비신뢰 자료 경계로 감싼다(`factcheck._untrusted` 재사용).
   - 모델이 general이어도 `GENERAL_BLOCK_SIGNALS`가 제목에 걸리면 시사로 올린다.
2. **확인 줄(인라인, 모달 없음):** 목록 위에 "시사 12건 (이미 확인 3건 제외 9건) · 약 $0.54 [검사 시작] [취소]"를 보인다. 시사가 0건이면 "시사로 보이는 글이 없습니다"만 보인다.
3. **판정(검사 시작):** 서버의 뒤쪽 작업자 하나가 시사 제목을 하나씩 판정한다.
   - 판정은 `verify([{id:"C1", claim: 제목, query: 제목}], title=제목, source_text="")`로 한다.
   - 결과는 글마다 보관한다.
   - 화면은 2초마다 진행 상황을 받아 "판정 중 4/9 · $0.24"를 보이고 칩을 채운다.
4. **칩:** 판정 하나를 칩 하나로 옮긴다(§4.2).
5. **토글:** "가짜 의심 숨기기 (n)"는 의심 칩 글을 목록에서 뺀다. 클라이언트에서 거르고, "안 맞는 글 숨기기"와 같은 방식이다.

### 4.2 판정 → 칩

| verify 결과 | 칩 | 색 | 뜻 |
|---|---|---|---|
| false | 의심 | bad | 보도와 다르거나, 반드시 보도될 공적 사건인데 보도가 없다 |
| unverified + public_event | 주의 | warn | 공적 사건인데 관련 보도를 못 찾았다 |
| unverified (그 밖) | 확인 안 됨 | mute | 제목만으로는 확인할 보도가 없다(낚시성·사연 글에 흔함) |
| partly | 주의 | warn | 핵심은 맞지만 과장·세부가 다르다 |
| true | 통과 | good | 보도로 확인된다 |
| 판정 실패 | 확인 실패 | mute | 다시 누르면 다시 시도한다 |

- 칩에 마우스를 올리면 판정 이유 한 줄과 출처 언론사가 보인다.
- 일반 글에는 칩을 달지 않는다.
- 칩 옆에 작게 "제목 기준"을 쓴다.

### 4.3 데이터: `work/_topics/fc_<site>_<번호>.json`

```json
{"v": 1, "title_hash": "sha256(제목)", "kind": "news|general",
 "status": "false|partly|true|unverified|failed|null", "public_event": false,
 "why": "…", "sources": [{"url": "…", "outlet": "…", "date": "…"}],
 "cost_usd": 0.06, "model": "anthropic/claude-opus-5.5", "at": "ISO"}
```

- 제목이 바뀌면(`title_hash`가 다르면) 무효로 본다. `TOPIC_FC_VERSION`을 올려도 무효가 된다.
- `kind`만 있고 `status`가 null이면 분류만 하고 판정은 안 한 상태다.
- 쓰기는 임시 파일 + `os.replace`로 한다(`factcheck.atomic_json` 재사용).
- 출처 URL은 `safe_url`을 거친다.

### 4.4 API (전부 `local_only`)

- `POST /api/topics/factcheck/estimate {source, items:[{no, title}]}` → `{news, done, todo, est_usd, per_item_usd}`
  - 분류는 여기서 한다(보관된 것은 다시 묻지 않음).
  - 한 번에 최대 200건이다.
- `POST /api/topics/factcheck/run {source, nos:[…]}` → `{started, total}`
  - 이미 돌고 있으면 409다.
  - 한 번에 최대 30건이고 넘으면 400이다. 사유는 "한 번에 30건까지 판정합니다"다.
  - 판정 작업자는 제작 대기열(Runner)과 따로 돈다. 제작을 막지 않는다.
  - OpenRouter 키가 없으면 409다.
- `GET /api/topics/factcheck/status` → `{running, done, total, cost_usd, error}`
- `POST /api/topics/factcheck/cancel` → 지금 판정 중인 건까지만 하고 멈춘다.
- 목록 응답 `items[]`에 보관된 결과 `fc: {kind, status, chip, why, sources, at} | null`을 붙이고, 응답 머리에 `fc_counts: {news, checked, doubt}`를 붙인다. 목록 응답은 네트워크를 부르지 않는다(보관된 것만).

## 10. 회의 결과와 개정 (2026-11-04 23:50, 앞 절보다 우선)

**판정**
- Sol: "판정: 수정 후 진행 — 높음 4 / 중간 7 / 낮음 1"
- Haiku: "판정: 수정 후 진행 — 높음 2 · 중간 5 · 낮음 4"

메인(Opus)이 아래처럼 정했다. 사용자가 자리를 비운 사이에 내린 결정이고, 되돌리기 쉬운 쪽을 골랐다.

### 10.1 칩 (§4.2를 대신한다)

| verify 결과 | 칩 | 색 | 숨기기 토글 |
|---|---|---|---|
| false + 출처 1개 이상 | 가짜 의심 | bad | 숨김 |
| false + 출처 없음 | 확인 안 됨으로 내린다(아래 10.2) | outline | 안 숨김 |
| unverified + public_event | 주의 | warn | 안 숨김 |
| unverified | 확인 안 됨 | outline | 안 숨김 |
| partly | 주의 | warn | 안 숨김 |
| true | 보도 확인 | ok | 안 숨김 |
| 실패 | 확인 실패 | outline | 안 숨김 |

- 칩 폭은 고정하지 않고 `whitespace-nowrap`으로 둔다.
- 판정 이유는 hover에만 두지 않는다. 가짜 의심·주의는 카드 안에 이유 한 줄을 늘 보인다. 나머지는 칩을 누르면 같은 자리에 펼친다(터치·키보드).
- 칩 옆에 "제목 기준"을 쓴다.

### 10.2 출처 없는 false (Sol 높음 1, 제작 단계 사실 확인에도 해당)

- `factcheck.verify`에서 출처가 없는 false는 unverified로 내리고, public_event는 그대로 둔다.
- 제작 단계에서는 `overall_status`의 "unverified + public_event → stop"이 그대로 막으므로 안전이 줄지 않는다.
- 이 수정은 feat/factcheck 쪽 작업으로 따로 한다(fc/astra-review).

### 10.3 견적과 실행의 묶음 (Sol 높음 2, Haiku 중간)

- estimate는 서버가 지금 목록 캐시에서 제목을 읽는다. 클라이언트가 보낸 제목을 그대로 쓰지 않고, 클라이언트는 `{source, nos}`만 보낸다.
- 서버는 `run_id`(무작위)와 `[{no, title, title_hash}]` 스냅샷을 10분 동안 보관한다.
- run은 `{run_id}`만 받는다. 스냅샷이 없거나 만료됐으면 409("목록이 바뀌어 다시 눌러 주세요")다.

### 10.4 결과 유효 기간 (Sol 높음 3)

- 분류(kind)는 제목이 같으면 계속 쓴다.
- 판정은 24시간 뒤 만료된다(속보가 확인될 수 있음). 만료된 글은 견적에서 다시 판정 대상에 든다.
- "다시 판정" 단추는 보이는 시사 글의 보관 판정을 무시하고 다시 견적한다.

### 10.5 비용 상한 (Sol 높음 4, Haiku 중간)

- 건당 예상치는 보관된 판정 비용의 p90을 쓴다. 표본이 10건 미만이면 $0.08이다. 견적은 `대상 건수 × 예상치`이다.
- 실행당 상한은 $2이다. 다음 건을 하면 상한을 넘을 것 같으면(누적 + 예상치 > $2) 멈추고 남은 건은 판정하지 않은 채로 둔다.
- 하루(KST) 상한은 $5이다. `config/topic_factcheck.json`에 두고, 넘으면 run이 409다.
- 비용이 None이면 예상치로 센다.
- 한 번에 30건 제한은 그대로다. 30건을 넘으면 확인 줄에 "앞 30건만 판정합니다"를 보이고, 끝나면 "다음 30건" 단추를 보인다.

### 10.6 묶음 분류 (Sol 중간 5, Haiku 중간)

- 새 함수로 만든다. `classify` 재사용이 아니다.
- 출력 계약은 `{"items":[{"i":번호,"kind":"news|general|uncertain"}]}`이다.
- 번호가 빠졌거나 잘못된 항목은 uncertain이다. uncertain은 시사 후보에 넣는다(놓치는 것보다 비용 쪽을 택함).
- 제목들은 `_untrusted`로 감싼다(dict 형태 `{"제목들": [...]}`). `GENERAL_BLOCK_SIGNALS`에 걸리면 news로 올린다.

### 10.7 실행 상태와 작업자 (Sol 중간 6·7·8, Haiku 중간)

- status는 `{run_id, source, state: idle|running|cancelling|done|stopped|failed, done, total, cost_usd, stop_reason, error}`이다. 화면은 자기 `run_id`의 상태만 본다.
- 작업자는 스레드 하나다. 시작은 잠금 안에서 한다. 취소 깃발은 몇 번 눌러도 같다. 취소해도 지금 판정 중인 1건(최대 120초)은 끝낸다.
- 항목 실패는 그 항목만 "확인 실패"로 보관하고 다음으로 간다.
- 402·429·하루 상한이면 실행 전체를 멈추고 stop_reason을 남긴다. 남은 건은 판정하지 않은 채로 둔다.
- 서버를 다시 켜면 상태는 idle이고, 보관된 결과는 그대로 남는다.

### 10.8 키·준비 상태 (Sol 중간 9, Haiku 낮음)

- 목록 응답 머리에 `fc_ready: bool, fc_note`를 둔다. 판정에 OpenRouter 키가 필요하므로, 키가 없으면 단추를 끄고 이유를 보인다.

### 10.10 그 밖

- 목록 응답의 `fc` 주석만 네트워크를 부르지 않는다(Haiku 낮음).
